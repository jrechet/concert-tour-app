This also gives us a well-tested "upcoming concerts" query that the CSV export can potentially reuse.

**Priority 2 — #351 Export concerts as CSV.** Slightly higher complexity since it introduces a new response format (streaming/text CSV) rather than JSON, and needs to decide whether it exports all concerts or supports the same filtering as #365. Dev should check whether to share query logic with #365's endpoint rather than duplicating filtering code.

**Risks:** Keep both endpoints as true additive changes — new routes/services only, no changes to existing models or database URLs, per past PR-quality issues (mismatched diffs, unscoped test-infra changes). Ensure both endpoints are covered by real tests exercising the actual filtering/CSV logic, not placeholder or unrelated test files, given the team's history of PRs that claimed functionality not present in the diff.
