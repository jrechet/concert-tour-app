## 4. Risks & Blockers

**Root cause identified:** the failing e2e tests (`test_feature_dashboard_concerts_default_includes_past`, `test_feature_dashboard_concerts_upcoming_only_hides_past`, `test_feature_dashboard_concerts_upcoming_only_show_past_overrides`) all call `/api/v1/dashboard/concerts` with an `upcoming_only` query param, but PR #440's title and scope only describe exposing a **`show_past`** toggle. The route appears to not recognize `upcoming_only` at all — the response always returns all 24 concert cards instead of filtering down to the expected 5–6, meaning the "hide past concerts" behavior isn't actually reachable via the param the tests (and likely the intended UI contract) expect.

This is a **param-naming mismatch between the route (#440) and its consumers** (template #441, e2e tests), not a flaky test issue. It needs a quick fix: either the route should also accept/normalize `upcoming_only`, or the e2e tests/template should be aligned to `show_past` — but the semantics differ (`upcoming_only=true` vs `show_past=false`), so this needs explicit confirmation of the intended contract before patching either side.

- `tests/e2e/` is currently untracked in git — worth confirming these were committed as part of the intended test suite rather than left as local scratch files.
